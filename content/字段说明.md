# content/ 目录字段说明

> 为什么单独写这个文档：JSON 标准**不允许写注释**（写了 `//` 或 `/* */` 会导致
> `JSON.parse` 直接抛错，整页白屏）。所以这三个 JSON 文件在注释版里保持**原样未改**，
> 字段含义统一说明在这里。

---

## 1. articles.json —— 文章目录（全站的核心索引）

站点所有列表、搜索、分类统计、相关文章推荐，数据来源都是这一个文件。
**新增文章必须同时改这里**，否则文章在站点上等于不存在。

```json
{
  "articles": [
    {
      "slug": "llm-engineering-guide",
      "title": "大模型工程化落地实践指南",
      "summary": "一句话摘要",
      "section": "行业思考",
      "topic": "AI 落地",
      "subtopic": "能力边界",
      "tags": ["LLM", "工程化", "AI"],
      "date": "2024-05-20",
      "published": true,
      "diagram": "llm-arch",
      "file": "articles/llm-engineering-guide.md"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `slug` | ✅ | 文章唯一标识，出现在 URL 里（`article.html?slug=xxx`）。只能用小写字母、数字、连字符。**改 slug = 换网址，旧链接会失效** |
| `title` | ✅ | 标题，显示在卡片和详情页大标题 |
| `summary` | ✅ | 一句话摘要，显示在卡片正文和详情页导语 |
| `section` | ✅ | 一级栏目。取值必须是 `assets/js/taxonomy.js` 里 `TAXONOMY` 的顶层 `name`（目前是 `学习笔记` / `行业思考`） |
| `topic` | ✅ | 二级分类，取值必须是该 section 下的 `children[].name` |
| `subtopic` | ⬜ | 三级分类，取值必须是该 topic 下的 `children[].name`。可以留空字符串 `""` |
| `tags` | ⬜ | 标签数组，用于搜索匹配和"相关文章"打分。**可以随便写**，不必在分类树里预先定义 |
| `date` | ✅ | 发布日期，格式 `YYYY-MM-DD`。排序用的是字符串比较，所以**必须补零**（`2024-05-08` 不能写成 `2024-5-8`） |
| `published` | ⬜ | 填 `false` 则隐藏该文章（草稿）。不写这个字段等同于 `true` |
| `diagram` | ⬜ | 目前只有 `llm-arch` 一个可选值：在详情页正文上方插入"整体架构"四列示意图。不需要就不写 |
| `file` | ⬜ | Markdown 正文路径（相对 content/）。不写则默认 `articles/<slug>.md` |

⚠️ **三个最容易踩的坑**

1. `section / topic / subtopic` 写的值和 `taxonomy.js` 里的中文名**不一致** → 文章不会出现在对应分类里，但也不会报错，只是"悄悄消失"。
2. `date` 写成 `2024-5-8` → 排序时字符串比较会把它排到 `2024-12-01` 之后（字典序 `2` > `1`）。
3. 加了 md 文件却忘了在 `articles.json` 里登记 → 文件传上去了但站点上找不到。

## 2. site.json —— 首页配置

```json
{
  "featured": ["slug-1", "slug-2", "slug-3", "slug-4"],
  "now": {
    "title": "现在在写什么",
    "text": "一段话说明最近在做什么",
    "topics": ["RAG 评估", "Agent 边界"]
  }
}
```

| 字段 | 说明 |
|------|------|
| `featured` | 首页精选文章的 slug 数组。**按数组顺序显示，最多放 4 个**（首页网格是 4 列）。⚠️ 不会自动用最新文章补位；slug 写错时该卡片会静默消失 |
| `now.title` | 「现在在写什么」区块的标题，缺省显示"现在在写什么" |
| `now.text` | 该区块的正文段落 |
| `now.topics` | 该区块下方的话题胶囊（字符串数组） |

## 3. profile.json —— 关于我

`about.js` 逐字段读取；每个字段都有兜底，缺失时会退回 `assets/js/config.js` 里的 `SITE` 值。

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 姓名/昵称，缺省用 `SITE.author` |
| `headline` | string | 一句话头衔，缺省用 `SITE.tagline` |
| `bio` | string | 个人简介段落 |
| `location` | string | 所在地，缺省用 `SITE.location` |
| `email` | string | 邮箱，缺省用 `SITE.email` |
| `links` | array | 外链按钮，每项 `{ "label": "显示文字", "href": "链接" }`，全部新窗口打开。`href` 可写 `mailto:` |
| `stack` | array | 技术栈字符串数组，渲染成一排胶囊 |
| `experience` | array | 工作经历，每项 `{ "title": 职位, "org": 公司, "period": "2022.01 — 至今", "desc": 描述 }` |
| `education` | array | 教育背景，每项 `{ "school": 学校, "major": 专业, "period": "2015 — 2019" }` |

⚠️ 数组字段（`links / stack / experience / education`）如果**不是数组**而是别的值，
`.map()` 会抛错导致整页渲染失败。删除时请保留空数组 `[]`，不要写成 `null`。

## 4. articles/*.md —— 正文与 Front Matter

每篇 Markdown 顶部可以写一段 Front Matter（用 `---` 包裹）：

```yaml
---
title: 文章标题
slug: my-new-post
summary: 一句话摘要
tags: [RAG, Milvus]
section: 学习笔记
topic: LLM 应用
subtopic: RAG
published: true
---
```

**与 articles.json 的关系：两边都写时，以 md 里的 Front Matter 为准**
（`loadArticle` 的合并顺序是 `{ ...articles.json的条目, ...md的FrontMatter }`）。
所以只改 md 不改索引也能生效，但**列表页读的是索引**，所以新增文章仍要登记。

解析器（`assets/js/markdown.js` 的 `parseFrontMatter`）只支持三种值类型：

| 写法 | 解析结果 |
|------|----------|
| `tags: [RAG, Milvus]` | 数组 `["RAG", "Milvus"]` |
| `published: true` | 布尔 `true` |
| `title: 文章标题` | 字符串（自动去掉两端引号） |

⚠️ 不支持嵌套结构、多行字符串、带冒号的键名。

## 5. 支持的 Markdown 语法

`markdown.js` 是手写的精简解析器，覆盖范围有限：

| 语法 | 支持 | 备注 |
|------|------|------|
| `# / ## / ###` | ✅ | 只认到三级，更深按普通段落处理；会自动生成锚点 id 并进目录 |
| 段落、空行分段 | ✅ | 段落内换行会被合并成空格（软换行不产生 `<br>`） |
| `- / * / +` 无序列表 | ✅ | ⚠️ 不支持嵌套缩进 |
| `1. 2. 3.` 有序列表 | ✅ | 同上 |
| `>` 引用块 | ✅ | 连续多行合并成一个 `<blockquote>` |
| ` ``` ` 代码块 | ✅ | 反引号后可写语言名，显示为窗口栏标签 |
| 表格 | ✅ | 需要标准的表头行 + `\|---\|` 分隔行；⚠️ 忽略对齐写法 |
| `---` 分割线 | ✅ | 单独一行 |
| 链接 `[a](b)`、图片 `![a](b)` | ✅ | 链接默认新窗口打开 |
| 行内代码 `` `x` ``、`**粗**`、`*斜*` | ✅ | |
| 嵌套列表、脚注、HTML 混排 | ❌ | 不支持 |
