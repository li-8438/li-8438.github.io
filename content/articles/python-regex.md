正则表达式是用「一套规则」去匹配字符串的工具，是爬虫、日志分析、表单校验里最常用的利器。它难在符号多、容易忘，但只要抓住「三种匹配方式 + 两类符号」这条主线，就能上手。

## 三种匹配方式

Python 用 `re` 模块，最常用的三个函数：

```python
import re

re.match(r"abc", "abc123")     # 从头匹配：开头上 abc，匹配成功
re.match(r"abc", "123abc")     # 开头不是 abc，返回 None

re.search(r"abc", "123abc")    # 是否包含：能匹配到 abc

re.findall(r"\d", "a1b2c3")    # 找所有：返回 ['1','2','3']
```

一句话区分：`match` 必须从头开始，`search` 找到即止，`findall` 返回所有匹配组成的列表。

## 单个字符匹配

| 写法 | 含义 |
|------|------|
| `.` | 任意字符（不含换行） |
| `[0-9a-zA-Z]` | 匹配集合内的任意一个字符 |
| `\d` | 数字 |
| `\w` | 字母、数字、下划线 |
| `\s` | 空白字符 |

## 量词：控制匹配次数

| 写法 | 含义 |
|------|------|
| `*` | 任意次（0 到多） |
| `+` | 至少一次 |
| `?` | 0 次或 1 次 |
| `{5}` | 固定 5 次 |
| `{3,5}` | 3 到 5 次 |
| `{5,}` | 至少 5 次 |

量词修饰它前面的那个字符。比如 `\d+` 表示「至少一个数字」，`ab+c` 能匹配 `abc`、`abbc`。

## 开头结尾匹配

用 `^` 和 `$` 锁住整段字符串的起止，常用于「格式校验」：

```python
re.match(r"^\d{11}$", "13800138000")   # 恰好 11 位数字，多一个少一个都不行
```

## 分组

用小括号 `()` 分组，既能整体匹配，也能单独提取：

```python
re.findall(r"(qq|sina|163)", "邮箱是 abc@qq.com")   # ['qq']

# 用 \1 引用第一个分组
re.match(r"<(h1)>\w*</\1>", "<h1>标题</h1>")        # 前后标签必须一致
```

一个注意点：`findall` 里有分组时，返回的是分组的内容而不是整体匹配。

## 贪婪与非贪婪

默认是「贪婪」——能多匹配就多匹配；加 `?` 变「非贪婪」——能少匹配就少匹配。这是正则最容易踩的坑：

```python
html = '<img src="a.jpg" class="x">'
re.findall(r'src="(.*)"', html)    # 贪婪：匹配到 'a.jpg" class="x'
re.findall(r'src="(.*?)"', html)   # 非贪婪：匹配到 'a.jpg'
```

规律：`.*` 和 `.+` 贪婪，`.*?` 和 `.+?` 非贪婪。提取「一对引号之间的内容」这类场景，几乎都要用非贪婪。

## 实战：提取网页图片地址

把前面串起来——抓一个网页，用正则把所有图片的 src 挖出来：

```python
import re
import httpx

client = httpx.Client()
res = client.get("https://www.tsinghua.edu.cn/")
img_list = re.findall(r'<img.*?src="(.*?)".*?>', res.text)

for url in img_list:
    if re.search(r"(jpg|png|gif)", url):
        print(url)
```

拆解这个正则：`<img` 开头，`.*?` 非贪婪跳过中间属性，`src="(.*?)"` 用分组提取 src 的地址，`.*?>` 收尾。三处「非贪婪」缺一不可，否则会一路匹配到文件末尾。

## 实战：解析大模型的输出

大模型输出经常「话里夹带私货」——一段解释里夹着一个 JSON。想从杂乱输出里抠出真正的 JSON，正则就派上用场了：

```python
import re

# 模型返回的文本里夹着一个 JSON 对象
text = '好的，结果如下：{"name": "user_a", "age": 18}，请查收。'

m = re.search(r'\{.*?\}', text)   # 非贪婪提取花括号里的 JSON
print(m.group(0))   # {"name": "user_a", "age": 18}
```

非贪婪 `.*?` 保证了只匹配到第一个 `}` 就停，不会被后面的话「贪」走。不过更稳妥的做法是「结构化输出」——让模型一开始就严格按 schema 返回，省掉这些脆弱的正则解析，见《用 Pydantic 做结构化输出》一文。

## 小结

正则记住这条主线就够用：**`match`/`search`/`findall` 决定怎么找，字符类和量词决定找什么，`()` 分组负责提取，`.*?` 负责别贪过头**。实际写的时候多靠「先用简单规则跑一次，再逐步收紧」，比一次写对更高效。到这里，Python 进阶的语言特性就讲完了，下一篇转入数据存储——用 MySQL 把数据真正存起来。
