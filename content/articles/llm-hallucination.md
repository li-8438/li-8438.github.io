用大模型最需要警惕的一件事：它生成的内容**看起来很专业，但可能是编的**。

这不是偶发故障，而是大模型工作方式的必然产物。要治理幻觉，得先理解它为什么必然发生。

## 一、幻觉的本质

大语言模型的工作是**基于上文预测下一个最可能出现的 token**。它追求的是语言序列的流畅与合理，而不是事实正确。

由此产生三个必然结果：

**概率生成本质。** 一个"听起来合理但错误"的回答，其生成概率可能远高于一个"正确但生硬"的回答。模型没有内置的真实性校验器。

**参数化知识的压缩失真。** 知识以某种形式被"压缩"进数百亿参数里，这个过程不是无损的。相似的概念会被混淆——比如两位生平相近的学者，模型可能把 A 的成就安到 B 头上。

**对"不知道"的忽视。** 模型没有明确的"我不知道"概念。遇到知识盲区时，为了完成生成任务，它倾向于按已有模式编造一个答案，而不是承认无知。

加上训练数据本身的局限——有截止日期、包含互联网上的错误信息、某些观点占主导——幻觉几乎是必然的。

### 一个典型案例

用户提问："请介绍《深度学习革命》一书的主要观点。"

模型回答："《深度学习革命》深入探讨了 CNN、RNN 和 Transformer 架构的演进，强调了数据与算力在 AI 发展中的核心作用……"——措辞专业，内容详实。

**而这本书并不存在。** 模型捕捉到"两位知名合著者"和"深度学习"这两个热门元素，把它们强行关联，编造了一本不存在的书以及它的内容。

这类幻觉最危险的地方在于：**越是外行的领域，你越难分辨**。

## 二、幻觉的两类分类

学术界通常把幻觉分成两大类，这个分类对治理有直接指导意义——**两类的成因不同，解法也不同**。

### 事实性幻觉（Factuality）

生成内容与**可验证的现实世界事实**不符。

- **事实不一致**：输出包含现实中能找到依据的事实，但与之矛盾
- **捏造事实**：输出包含无法与现实世界知识验证的内容

典型：编造不存在的书籍、论文、数据、法条。

### 忠实性幻觉（Faithfulness）

生成内容与**用户指令或输入上下文**不一致。

- **不遵循指令**：输出与用户要求不符
- **不遵循上下文**：输出与用户提供的上下文信息矛盾
- **逻辑不一致**：推理步骤之间、或推理步骤与结论之间矛盾

典型：你明明给了文档让它基于文档回答，它却用自己的知识回答；或者推理第一步还算对，第三步莫名跳到错误结论。

**这个分类为什么重要**：事实性幻觉靠"给外部知识"（RAG）治，忠实性幻觉靠"约束生成过程"（提示词、CoT）治。用错方向，白费功夫。

## 三、成因拆解

### 事实性幻觉的三个来源

**训练数据的局限与噪音**

- 知识过时：训练数据有截止日期，之后的事件模型只能猜
- 数据不准确：互联网语料本身包含大量错误、偏见、矛盾内容
- 代表性偏差：某些观点在训练数据中占主导，少数但正确的认知被淹没

**模型是"关联引擎"而非"知识库"**

- 概率生成本质，追求流畅而非正确
- 参数化知识压缩失真，相似概念混淆
- 遇到盲区时编造而非承认无知

**缺乏事实核查机制**

标准生成是单向、自回归的。模型不会在输出每句话后去查数据库——它做不到，也没有这个机制。

### 忠实性幻觉的三个来源

**指令理解偏差**

- 指令模糊、复杂或含多重约束时，模型只执行它"认为"的核心任务，忽略其他细节
- 预训练学到的固有模式会覆盖特定指令（比如你要求某种格式，它偏用常见格式）

**上下文处理的局限**

- 有限的上下文窗口，长输入仍会出现"中间遗忘"
- 注意力机制可能没把输出关联到最相关的上下文部分
- 上下文本身冲突时，模型无法分辨哪个对

**推理能力不足**

- 多步推理中某一步的微小错误，会导致后续全部崩塌
- 模型逐词生成，不会先规划完整推理路径

## 四、四层解法

面对幻觉，业界形成了多层次的技术方案。它们不是互相替代，而是作用于不同层面。

### 第一层：提示词工程（交互界面）

**作用层面**：交互层，在推理阶段约束模型行为。

核心思路是引导结构化思考，明确答案边界。三个具体手法：

**思维链与自我验证**

```
请回答"哪个国家最早拥有核武器？"。请分步推理，并在给出最终答案前，
检查是否存在与你的中间步骤结论相矛盾的事实。
```

**提供参考并要求引用**

```
请基于以下文档回答问题："[文档内容]..."。
你的回答必须严格来自上述文档，如果文档中没有相关信息，
请明确回答"根据提供文档，无法得知"。如果可能，请引用原文句子。
```

注意最后那句——**允许模型说"不知道"**，是降低幻觉最有效的一招。不给这个出口，模型就只好编。

**要求输出置信度**

```
请回答以下问题，并随后以"我对此答案的置信度为：高/中/低"的格式给出你的置信度评估。
```

**局限**：提示词无法赋予模型新知识。对**知识盲区**导致的幻觉，它治标不治本。

### 第二层：RAG（系统架构）

**作用层面**：系统架构层，给模型接上外部知识源。

工作流程是"检索 → 增强 → 生成"：把用户查询拿去检索相关文档片段 → 片段作为上下文与问题拼接 → 模型基于这个"证据充足"的提示词生成答案。

对比一下效果。问"公司 2024 年 Q1 的云业务营收增长率是多少？"：

- **没有 RAG**：模型根据训练数据里其他公司的财报模式，编一个数字（比如"15%"）
- **有 RAG**：系统从内部财报 PDF 里检索到"本季度云业务营收为 XX 亿元，同比增长 22%"，模型回答"根据 2024 年 Q1 财报，增长率为 22%"——准确、可信、可溯源

**RAG 是治理事实性幻觉的主力**。它从根本上解决了"知识更新"和"私有知识"两个问题。

**局限**：不能解决忠实性幻觉。检索到了正确文档，模型仍然可能不按文档说、或者推理时跑偏。

### 第三层：模型微调（模型内部）

**作用层面**：模型参数层，重塑模型的"世界观"。

用高质量的领域数据对模型再训练，强化产生正确事实的模式，抑制胡编乱造。

两种路线：

- **全参数微调**：效果显著，但成本高，且可能导致"灾难性遗忘"
- **LoRA 微调**：当前主流。通过注入并训练少量适配器层，以极低成本实现接近全参数微调的效果，同时保留通用能力

典型场景：医疗机构用权威药物说明书构建数十万条问答对，用 LoRA 微调基础模型。微调后面对药物问题，回答严格基于说明书，幻觉率显著降低——它被"塑造"成了领域专家，而不是泛泛而谈的通才。

**局限**：微调擅长注入**稳定的领域知识和风格**，不适合注入**频繁变动的事实**。公司制度每季度都变，用微调去记是不现实的——这种场景该用 RAG。

### 第四层：AI Agent（系统架构）

**作用层面**：系统架构层，引入"批判与验证"的思维循环。

Agent 把模型从"内容生成器"提升为"动作执行者"，天然包含对抗幻觉的机制：

**工具使用**：不确定时调用搜索工具查最新信息，而不是依赖内部记忆。

**代码解释器**：数学和逻辑问题写代码精确执行，避免计算和推理错误。

**多步验证**：设计验证循环——先生成答案，再换一种方式（如搜索）去验证一致性。

对比一下"总结最近一周量子计算突破的三篇重要论文"这个任务：

- **单一模型**：极可能编造三篇看似合理、实际不存在的论文标题和摘要
- **Agent 工作流**：规划（需要搜索）→ 执行（调学术搜索 API 拿真实论文列表）→ 验证（对每篇再调工具获取官方摘要）→ 生成（基于真实检索结果撰写）

Agent 通过把"思考"和外部"验证"结合，构建了动态的自我修正系统。

## 五、四层方案怎么组合

| 技术 | 作用层面 | 核心价值 | 适用场景 |
| --- | --- | --- | --- |
| 提示词工程 | 交互界面 | 低成本、即时生效 | 简单事实查询、逻辑推理 |
| 模型微调 | 模型内部 | 塑造领域专家，减少领域内幻觉 | 医疗、法律、金融等专业领域 |
| RAG | 系统架构 | 提供实时、准确的外部知识证据 | 知识库问答、客服、企业数据分析 |
| AI Agent | 系统架构 | 动态规划与验证，处理开放任务 | 数据分析、研究报告、复杂问题求解 |

一个关键判断：**先分清你的幻觉是哪种**。

- 模型**不知道**答案（知识盲区）→ 用 RAG 或微调补知识
- 模型**知道但不按你说的做**（指令遵循问题）→ 用提示词工程或 CoT 约束生成

用错了方向，再怎么优化也是徒劳。

工业级系统的现实是**多种技术融合**。比如一个金融分析 Agent：核心是经过 LoRA 微调的金融模型（模型层），通过 RAG 接入实时行情和财报（知识层），并能自主调用计算工具做估值建模（验证层）。

## 小结

幻觉不是 bug，是**概率生成 + 参数化知识 + 无核查机制**这三者的必然产物。

分类上要区分**事实性幻觉**（与现实不符，靠 RAG 补知识）和**忠实性幻觉**（与指令/上下文不符，靠提示词约束生成）。成因不同，解法不同，判断错了就是白忙。

四层解法中：RAG 是治理事实性幻觉的主力，也是当前企业落地的标配；微调擅长注入稳定的领域知识；提示词工程是零成本的即时手段；Agent 用验证循环处理开放任务。

没有单一银弹。一个健壮的系统往往是"微调过的模型大脑 + RAG 知识心脏 + Agent 协作四肢"的组合。

要把 RAG 真正落地，就得理解它的完整链路——从文档切分、向量化、混合检索到上下文构建和生成。这一整条链路怎么设计，见 [RAG 核心链路：从提问到带引用的答案](article.html?slug=rag-core-pipeline)。
