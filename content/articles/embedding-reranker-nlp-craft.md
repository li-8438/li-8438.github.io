如果你是在 2023 年之后开始接触 NLP 的，很可能有过这么一个阶段：看着分词、TF-IDF、BM25、词向量这些词，心里嘀咕——**这些还有用吗？** 大模型不是把这些都内化了吗？

我的判断是：**不但有用，而且比大模型出现之前更值钱了。**

原因不是这些技术变强了，而是它们的**位置变了**。过去它们是"让模型学会知识"的手段，现在它们是"给模型看对东西"的手段。前者可以被参数规模碾压，后者不能。

## 一、变的是什么：从"让模型学会"到"让模型看到"

传统 NLP 的隐含假设是：知识要**进到模型参数里**。所以才有预训练、微调、持续学习这一整套。embedding 在这个语境下，主要是模型的中间产物或下游任务的输入特征。

LLM 时代出现了一个关键转向：**知识可以不进参数，可以放在上下文里。**

这带来一个直接后果——**"给模型看什么"变成了一个独立的工程问题**，而它恰好就是老 NLP 的主场：

| 老手艺 | 在 LLM 时代的位置 |
| --- | --- |
| 分词 / 切分 | chunk 边界的确定、中文分词对 BM25 的影响 |
| 词向量 / 句向量 | embedding 模型，检索的第一阶段 |
| TF-IDF / BM25 | 稀疏检索，混合检索的一半 |
| 文本相似度 | 向量召回、去重、记忆检索 |
| 文本匹配（精排） | cross-encoder reranker |

**没有一项消失，全都在，而且都变成了系统里可独立调优的一环。**

这也是为什么招聘市场上"RAG 架构设计""内存系统实现"这类要求涨得比"提示词工程"快——它们本质上是 NLP 工程，不是提示词技巧。

## 二、为什么检索必须分两阶段：bi-encoder 与 cross-encoder

这是本篇的核心，也是很多人用错了 reranker 的根源。

### Bi-encoder（双编码器）

query 和文档**分别**编码成两个向量，然后算余弦相似度。

```python
# query 和 doc 各自独立过一遍模型，互不看见
q_vec = model.encode(query)        # 一次前向
d_vec = model.encode(document)     # 一次前向
score = cosine(q_vec, d_vec)       # 一次点积
```

**关键性质**：文档的向量可以**离线算好、存进索引**。查询时只需要给 query 算一次向量，然后对亿级向量做近似最近邻搜索。

代价是：**query 和文档在编码阶段从未交互过。** 模型必须在完全不知道问题的情况下，把一段文本压成一个固定长度的向量。这个压缩必然丢信息。

### Cross-encoder（交叉编码器）

把 query 和文档**拼在一起**送进模型，直接输出一个相关性分数。

```python
# query 和 doc 拼接后联合编码，互相可见
score = model.predict(f"[CLS]{query}[SEP]{document}[SEP]")
```

**关键性质**：模型能看到两者之间的交互——哪些词对上了、哪些语义对不上、指代是否成立。所以它的判断准得多。

代价是：**每一对 (query, doc) 都要跑一次完整前向。** 无法预先计算，无法用 ANN 加速。对百万级语料做全量 cross-encoder 打分是不现实的。

### 于是有了两阶段

| 阶段 | 用什么 | 从多少到多少 | 目标 |
| --- | --- | --- | --- |
| 召回（retrieval） | bi-encoder + 稀疏 | 全库 → 50-200 | 快，尽量别漏 |
| 精排（rerank） | cross-encoder | 50-200 → 5-10 | 准，排对顺序 |

**召回阶段用速度换覆盖率，精排阶段用算力换准确率。** 这不是妥协，这是在两组约束下的最优解。

理解这一点之后，很多"最佳实践"就不需要背了：

- 为什么 reranker 的输入不能太多？因为 cross-encoder 是线性开销
- 为什么不能直接用 reranker 做全库检索？因为无法预计算
- 为什么加了 reranker 收益这么大？因为它补上了 bi-encoder 丢失的交互信息

## 三、稀疏检索为什么没被淘汰

按理说，有了强大的稠密 embedding，BM25 早该进博物馆了。它没有，而且在 2026 年反而成了标配的一半。

原因是**稠密检索有一个结构性盲区：精确标识符。**

用户搜 `CVE-2024-1234`、`getUserById`、型号 `XR-200B`、错误码 `E0142`——这些字符串在嵌入空间里彼此高度相似，因为它们共享几乎相同的字符分布，语义模型对这种差异不敏感。而 BM25 关心的是精确词项匹配，天然擅长这个。

**两者失败的方式是互补的**，这就是混合检索有效的原因：

| 查询类型 | 稠密 | BM25 |
| --- | --- | --- |
| "退款流程是怎样的" | 好 | 一般 |
| "XR-200B 的固件版本" | 差 | 好 |
| "如何处理客户投诉升级" | 好 | 一般 |
| "错误码 E0142 怎么解决" | 差 | 好 |

融合两者最常用的方法是 **RRF（Reciprocal Rank Fusion，倒数排名融合）**：

```
score(d) = Σ  1 / (k + rank_i(d))     # k 通常取 60
```

用排名而不是原始分数，规避了两个检索器分数量纲不可比的问题——这是个很聪明的工程取舍。

顺带一提，中文场景下 BM25 还多一层麻烦：**中文没有空格，需要分词才能建倒排索引。** 分词质量直接影响稀疏检索的效果，这也是"老手艺"在中文场景里格外没过时的原因之一。

## 四、embedding 模型的三个现实约束

选 embedding 模型时，有三件事比榜单分数更重要。

**约束一：维度直接决定存储和成本。** 常见选择：text-embedding-3-small 是 1536 维，bge-m3 是 1024 维，nomic-embed-text 是 768 维，jina-embeddings-v3 是 1024 维。维度翻倍，存储和索引内存大致翻倍。

**约束二：语言匹配比你想的重要。** 针对英文优化的模型在中文语料上会明显退化。中文场景里 bge-m3、jina-embeddings-v3、通义 text-embedding-v3 是更稳妥的选择。**用真实语料测过再定，别看多语言支持的宣传。**

**约束三：换模型要全库重建。** 这可能是最贵的一个约束。不同模型的向量空间不可比，升级 embedding 模型意味着重新嵌入整个语料库。所以选型时要把"这个模型会不会很快过时"算进去，并且预留 re-index 的窗口。

## 五、稀疏 + 稠密一体：bge-m3 这类模型为什么重要

2026 年一个值得注意的进展是**同一个模型同时产出稀疏向量和稠密向量**（bge-m3 是代表）。

它的实际意义不只是"少部署一个模型"：

- **索引只建一份**，不用维护 BM25 倒排和向量索引两套
- **更新只做一次**，不会出现在两个索引之间不一致的窗口期
- **融合更自然**，两种分数来自同一个模型的同一套语义理解

对资源有限的团队，这基本就是默认选择了。

## 六、什么时候该微调 embedding 模型

我的建议是：**绝大多数时候不该。**

微调 embedding 需要的是大量高质量的 (query, 相关文档) 标注对。这个数据的获取成本很高，而且：

- 通用 embedding 模型的能力已经相当强，冷启动效果通常可接受
- 微调带来的收益往往小于把精力放在分块策略和 reranker 上
- 微调会让换模型变得更难，锁定更深

**值得微调的信号**：你的领域有大量专有词汇（医疗术语、法律条文、内部产品名），且通用模型在这些词上的检索表现明显崩坏，同时你能拿到至少几千条真实标注。

**在这之前，先试 reranker。** 它的性价比高得多。

## 七、容易踩的坑

**混用 embedding 模型。** 一部分文档用 A 模型嵌入，另一部分用 B 模型。两个向量空间不可比，检索出来的结果会莫名其妙。统一模型，并在元数据里记录模型版本。

**把 reranker 当检索器用。** 对全库跑 cross-encoder，慢到不可用。它是精排器，只在召回之后的几十到几百条候选上工作。

**忘记归一化。** 用点积做相似度时，如果向量没归一化，长度会污染相似度分数。要么用余弦，要么确保归一化——而且召回和入库必须用同一套处理。

**只看英文榜单选中文模型。** MTEB 上的高分不等于中文语料上的高分。用你的真实 query 测 Recall@K。

**认为 embedding 只是"调个 API"。** 实际上它决定了你检索质量的上限，而检索质量决定了整个 RAG 系统的上限。这是值得投入时间理解的一层，不是随手选默认值的配置项。

## 小结

把这篇文章放进更大的图景里看：

> **大模型的出现并没有消灭 NLP 工程，只是把它从模型内部搬到了系统外围——而外围恰恰是你能控制、能调优、能形成差异的地方。**

模型对所有人都是一样的（同一个 API、同样的价格），但**你的检索做得好不好，是只属于你自己的差异**。这就是为什么"检索工程"在 2026 年成了稀缺技能。

对学 NLP 的人来说，这是个好消息：你学的那些东西没有白学，它们只是换了个更值钱的位置。
