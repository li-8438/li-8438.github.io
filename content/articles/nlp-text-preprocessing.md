英文天然用空格分好了词，中文没有——"下雨天留客天留我不留"，不同的切法意思完全不同。所以中文 NLP 的第一道关卡永远是**分词**。

这一篇讲中文文本预处理的基本功：分词、自定义词典、词性标注、命名实体识别。这些技术在深度学习时代没有过时，反而在检索、特征工程等场景里依然高频使用。

## NLP 的两大任务方向

自然语言处理分两大类：

**自然语言理解（NLU）** —— 让机器读懂文本：分词、词性标注、命名实体识别、情感分析、意图识别、文本分类

**自然语言生成（NLG）** —— 让机器写出文本：机器翻译、文本摘要、对话生成、代码生成

传统 NLP 主要攻克 NLU，大模型的突破主要在 NLG。但无论哪个方向，**预处理的质量直接决定上限**——垃圾进，垃圾出。

## jieba 分词：三种模式

jieba 是中文分词最常用的工具，提供三种切分模式。

### 精确模式（最常用）

**保证语义完整**，把句子最合理地切开，适合文本分析：

```python
import jieba

sentence = '我爱自然语言处理技术'

result = jieba.cut(sentence)      # 返回生成器
result_list = jieba.lcut(sentence)  # 返回列表，更常用

print(result_list)
# ['我', '爱', '自然语言', '处理', '技术']
```

`cut` 返回生成器（省内存，适合大文本），`lcut` 直接返回列表（方便查看和处理）。日常用 `lcut` 居多。

### 全模式

**尽可能多地切出所有可能的词**，速度快但会有歧义：

```python
jieba.lcut(sentence, cut_all=True)
# ['我', '爱', '自然', '自然语言', '语言', '处理', '技术']
```

注意"自然语言"被同时切成了"自然"和"自然语言"——因为它把所有可能的词都列出来了。这种模式适合**搜索引擎建索引**（多切一些能提高召回），不适合文本分析。

### 搜索模式

**把长词再切成短词**，专为搜索引擎设计：

```python
jieba.lcut_for_search('研究员硕士毕业于中国科学院计算所')
# ['研究', '研究员', '硕士', '毕业', '于', '中国', '科学', '学院', '科学院', '中国科学院', '计算', '计算所']
```

注意"研究员"被同时切成了"研究"和"研究员"，"中国科学院"也既保留完整形式、又切出了"中国""科学""学院"等短词。这样用户搜"科学"也能命中这篇文档，提高召回率。

### 三种模式怎么选

| 模式 | 特点 | 适用场景 |
|---|---|---|
| 精确模式 | 语义完整，无冗余 | 文本分析、分类、情感分析（默认） |
| 全模式 | 切出所有可能词，有歧义 | 需要高召回的场景 |
| 搜索模式 | 长词再切短词 | 搜索引擎索引构建 |

## 自定义词典：解决领域词切错

jieba 的通用词典不认识专业术语，这是最常见的问题：

```python
jieba.lcut('大模型应用开发需要掌握RAG技术')
# 可能切成 ['大', '模型', '应用', '开发', '需要', '掌握', 'RAG', '技术']
# "大模型"被切开了！
```

解决办法是加载**自定义词典**。

**第一步**：准备一个 `userdict.txt`，每行一个词，格式为：

```
词  词频  词性
大模型 1000 n
RAG 500 nz
向量数据库 800 n
```

词频和词性可以省略，但**建议填词频**。当一个词是另一个词的子串时（比如"模型"和"大模型"），词频设置得更大，才会优先切出长词。

**第二步**：加载词典

```python
jieba.load_userdict('userdict.txt')

jieba.lcut('大模型应用开发需要掌握RAG技术')
# ['大模型', '应用', '开发', '需要', '掌握', 'RAG', '技术']
```

**领域适配是分词效果好坏的关键**。做医疗 NLP 就加载医学词典，做法律就加载法律词典。这一步的收益往往比换更复杂的模型还大。

也可以临时动态调整：

```python
jieba.add_word('大模型', freq=2000)   # 临时加词
jieba.del_word('自然语言')            # 临时删词
jieba.suggest_freq(('大', '模型'), True)  # 调节词频使"大""模型"能被切开
```

## 词性标注 POS

词性标注给每个词打上语法标签（名词 n、动词 v、形容词 a 等），返回 `(词, 词性)` 的元组列表：

```python
from jieba import posseg as pseg

words = pseg.cut('我爱北京天安门')
for word, flag in words:
    print(f'{word}({flag})', end=' ')
# 我(r) 爱(v) 北京(ns) 天安门(ns)
```

常见词性标签：

- `n` 名词、`nr` 人名、`ns` 地名、`nt` 机构名
- `v` 动词、`a` 形容词、`d` 副词
- `m` 数词、`q` 量词、`t` 时间词
- `x` 非语素字（标点等）

**实用场景**：只用名词和动词做关键词提取、过滤掉停用词和标点、按词性筛选特征。

```python
# 只保留名词和动词作为关键词
keywords = [w for w, flag in pseg.cut(text)
            if flag.startswith('n') or flag.startswith('v')]
```

## 命名实体识别 NER

NER 的任务是**识别文本中的专有实体**：人名、地名、机构名、时间、产品名等。

```python
import jieba.analyse

text = '马云在杭州创办了阿里巴巴集团'
# jieba 的 NER 能力有限，实际项目通常用专门工具
for word, flag in pseg.cut(text):
    if flag in ('nr', 'ns', 'nt'):   # 人名/地名/机构名
        print(f'{word} → {flag}')
# 马云 → nr
# 杭州 → ns
# 阿里巴巴 → nt
```

jieba 的 NER 是基于词典和词性的轻量方案，**准确率有限**。生产环境通常用专门工具：

- **LTP**（哈工大）—— 中文 NLP 全套工具，准确率高
- **HanLP** —— 功能全面，支持多语言，社区活跃
- **spaCy** —— 英文首选，速度快，工业级
- **BERT-NER** —— 用预训练模型做序列标注，效果最好

NER 的核心业务价值是**从非结构化文本里抽出结构化信息**。比如新闻里抽出"谁、在哪、做了什么"，客服工单里抽出"产品名、故障类型、时间"。

## 关键词提取

分词之后最常见的下游任务是提取关键词，jieba 内置了 TF-IDF 和 TextRank 两种算法：

```python
import jieba.analyse

text = '机器学习是人工智能的一个重要分支，深度学习又是机器学习的一个分支'

# TF-IDF：基于词频和逆文档频率
print(jieba.analyse.extract_tags(text, topK=5, withWeight=True))

# TextRank：基于图排序，不需要语料库
print(jieba.analyse.textrank(text, topK=5))
```

**TF-IDF** 需要语料库算逆文档频率，适合有大量文档时；**TextRank** 单篇文档就能算，适合处理单条文本。

## 大模型应用开发中的落地

**第一，分词决定中文 RAG 的检索质量**。向量检索虽然不依赖分词，但**关键词检索（BM25）依赖**。生产级 RAG 几乎都用**混合检索**（向量 + BM25），而 BM25 的效果直接取决于分词质量。给 jieba 加载领域词典，是提升 RAG 召回率**性价比最高**的一招。

**第二，自定义词典要和大模型的词表对齐**。用 jieba 切出来的词如果和大模型 tokenizer 的切法差异太大，会误导你对 token 消耗的估算。理解这点很重要：**jieba 的分词是给人看和给 BM25 用的，大模型内部用的是完全不同的子词切分**（BPE/WordPiece，下一篇详讲）。

**第三，分词是文本去重和聚类的前置步骤**。清洗知识库时，先分词再用 TF-IDF 向量化，然后算相似度去重，比直接对原文算相似度更准确，尤其对长文档。

**第四，NER 是结构化抽取的利器，但大模型正在取代它**。传统 NER 需要标注大量数据才能训好，而且只能识别预定义的实体类型。大模型做零样本抽取（用提示词直接要求"抽出所有公司名称"）**开发成本几乎为零，且能应对没见过的实体类型**。实践中的选择：

- 实体类型固定、数据量大、要求低延迟 → 传统 NER 模型
- 实体类型多变、标注数据少、需要快速验证 → 大模型抽取

**第五，分词能帮你理解 token 消耗的构成**。中文在大模型里通常 1 个字 ≈ 1~2 个 token，但专业术语、英文缩写可能一个词就是好几个 token。用 jieba 分词后再估算，比按字数乘系数准确得多，这对成本预算很有用。

## 小结

中文 NLP 的预处理三步走：**分词**（精确模式用于分析、全模式/搜索模式用于检索）、**自定义词典**（解决领域词切错，性价比最高）、**词性标注与 NER**（抽取结构化信息）。工具上 jieba 能做基础工作，生产环境可换 HanLP、LTP 或 BERT 系列模型。
