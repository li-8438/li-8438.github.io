模型只认数字。所以处理文本的第一步永远是：**把词变成向量**。

这个转换看起来简单，但怎么转、转成什么样，直接决定了模型能不能理解语义。这一篇讲词向量的演进——从最朴素的 One-Hot，到能表达"国王 - 男人 + 女人 = 王后"的 Word2Vec。

## One-Hot 编码：能表示，但没有语义

最直接的想法：给词表里的每个词一个编号，用一个向量表示，该位置为 1、其余为 0。

```python
words = ['国王', '王后', '男人', '女人', '巴黎', '法国', '伦敦', '英国']

# 1. 建立词到索引的映射
word_index = {word: i for i, word in enumerate(words)}

# 2. 把每个词转成稀疏向量
def one_hot(word, size):
    vec = [0] * size
    vec[word_index[word]] = 1
    return vec

print(one_hot('巴黎', len(words)))
# [0, 0, 0, 0, 1, 0, 0, 0]
```

### 两个致命缺陷

**第一，维度灾难**。词表有多大，向量就有多少维。中文常用词几万个，GPT 级别的词表十万起步——每个词都是十万维的向量，其中只有一个 1。存储和计算都极其浪费。

**第二，完全没有语义**。任意两个词的 One-Hot 向量**互相正交**（点积恒为 0）。这意味着"法国"和"香蕉"这种八竿子打不着的词，跟"法国"和"巴黎"这种语义紧密的词，在向量空间里的距离完全一样——模型看不出任何关联。

我们真正想要的是：**语义相近的词，向量也相近**。

## 分布式表示：让向量承载语义

这个想法叫**分布式假设（Distributional Hypothesis）**：**一个词的含义，由它周围经常出现哪些词决定**。

"国王"和"君主"经常出现在相似的上下文里（王冠、王宫、统治），所以它们的向量应该接近。

**Word2Vec** 就是用神经网络把这个想法变成现实的方法。

## Word2Vec 的核心思路

Word2Vec 的设计非常巧妙：**它用"预测上下文"这个任务来训练一个浅层神经网络，但我们真正想要的不是预测能力，而是训练过程中学到的权重矩阵**。

具体结构：

```
输入层（词的 One-Hot 向量）→ 权重矩阵 W → 隐藏层（词向量）→ 权重矩阵 W' → 输出层（预测）
```

训练完之后，**输入层的权重矩阵 W 的每一行，就是对应词的词向量**。

打个比方：我们让网络做"根据上下文猜中间词"的填空题，网络为了做好这道题，必须把语义相近的词放在向量空间里相近的位置。**词向量是这个训练过程的副产品，而这个副产品才是我们真正想要的**。

## CBOW：用两侧预测中间

**CBOW（Continuous Bag of Words）** 的任务是：**给你一个词左右两侧的上下文，预测中间这个词**。

```
输入："我 爱 ___ 学习"
上下文：["我", "爱", "学习"]
目标：预测中间的词 —— "自然语言"
```

训练流程：

1. 把上下文词的 One-Hot 向量输入网络
2. 经过前向传播（加权求和），得到预测值
3. 用预测值和真实值算损失
4. 反向传播更新权重 W
5. 训练结束后，W 的每一行就是一个词的词向量

## Skip-gram：用中间预测两侧

**Skip-gram** 正好反过来：**给你中间的词，预测它左右两侧的上下文**。

```
输入："自然语言"
目标：预测上下文 —— ["我", "爱", "学习"]
```

### 两者怎么选

| 对比项 | CBOW | Skip-gram |
|---|---|---|
| 任务 | 上下文 → 中心词 | 中心词 → 上下文 |
| 速度 | 快 | 慢（要预测多个词） |
| 小数据集 | 效果较好 | 效果一般 |
| 生僻词 | 表现一般 | **表现更好** |
| 大数据集 | 一般 | **效果更好** |

**实践建议**：数据量小用 CBOW（快且够用），数据量大或关注生僻词用 Skip-gram。实际工程中 Skip-gram 用得更多，因为它对低频词的表示质量更高。

## 词向量能做什么

Word2Vec 训练出的向量有一个惊人的性质：**语义关系可以用向量运算表达**。

```
vec(国王) - vec(男人) + vec(女人) ≈ vec(王后)
vec(北京) - vec(中国) + vec(法国) ≈ vec(巴黎)
```

这说明向量空间里**编码了语义和类比关系**——"性别"是一个方向，"首都-国家"是另一个方向。

还有个实用特性：语义相近的词，余弦相似度接近 1。

```python
from sklearn.metrics.pairwise import cosine_similarity

# 假设已经有词向量字典 vectors
sim = cosine_similarity([vectors['苹果']], [vectors['香蕉']])
```

## 用 gensim 训练词向量

实际项目中不需要自己写 Word2Vec，用 gensim 几行就搞定：

```python
from gensim.models import Word2Vec
import jieba

# 1. 准备语料：每篇文档切成词列表
sentences = [
    ['我', '爱', '自然语言', '处理'],
    ['深度', '学习', '是', '机器学习', '的', '分支'],
    # ... 更多语料
]

# 2. 训练
model = Word2Vec(
    sentences,
    vector_size=100,   # 词向量维度，常用 100~300
    window=5,          # 上下文窗口大小
    min_count=5,       # 忽略出现次数少于 5 的词
    sg=1,              # 1=Skip-gram, 0=CBOW
    workers=4
)

# 3. 使用
print(model.wv['自然语言'])              # 查看词向量
print(model.wv.most_similar('国王', topn=5))  # 找最相似的词
print(model.wv.similarity('苹果', '香蕉'))    # 算两个词的相似度

model.save('word2vec.model')
```

## 词向量的局限性

Word2Vec 相比 One-Hot 是巨大进步，但有一个**根本缺陷：一个词永远只有一个向量**。

这导致它无法处理一词多义：

```
"苹果很好吃"       → 苹果 = 水果
"苹果发布新手机"    → 苹果 = 公司
"苹果股价上涨"      → 苹果 = 公司
```

Word2Vec 给"苹果"一个固定的向量，等于把水果和公司的语义平均在一起，两个意思都不准。

这个问题的解决要等到 **ELMo 和 BERT**——它们根据上下文动态生成词向量，同一个词在不同句子里有不同的表示（这叫**上下文相关表示**）。这是通向大模型的关键一步。

另外，Word2Vec 也解决不了**未登录词（OOV）**问题：训练时没见过的词，就没有对应的向量。这个问题的解决方案是**子词切分**，也就是下一篇的主题。

## 大模型应用开发中的落地

**第一，Embedding 就是现代版的词向量，只不过粒度更细**。现在做 RAG 用的 Embedding 模型，输出的是**整句/整段的向量**而不只是单个词。但底层思想完全一致：把语义编码成向量，用向量距离衡量语义相似度。理解 Word2Vec，就理解了所有 Embedding 模型的原理。

**第二，`nn.Embedding` 就是一个可训练的查表层**。在 PyTorch 里，词向量层长这样：

```python
import torch.nn as nn

# 词表 10 万，每个词 768 维
embedding = nn.Embedding(num_embeddings=100000, embedding_dim=768)

# 输入 (batch, seq_len) 的整数 ID
input_ids = torch.tensor([[1, 234, 5678]])
# 输出 (batch, seq_len, 768) 的向量
vectors = embedding(input_ids)
```

**这个层的权重就是词表矩阵，训练过程中会被不断调整**——和 Word2Vec 里"用 W 矩阵当词向量"是同一个设计。

**第三，词向量的维度选择有讲究**。Word2Vec 时代常用 100~300 维，现代 Embedding 模型常用 384 / 768 / 1024 / 1536 维。维度越高表达力越强，但存储和检索成本也越高。RAG 场景下的经验：**768 维够用，1536 维更好，超过 1536 收益递减**。

**第四，静态词向量在某些场景仍有价值**。Word2Vec 训练快、体积小（几十 MB）、推理无需 GPU，在**同义词挖掘、商品推荐、广告召回**这类对延迟敏感、语义要求不极致的场景依然广泛使用。不要盲目上大模型。

**第五，"一词多义"是选型的关键判据**。如果你的应用里同一个词在不同上下文含义差别很大（比如做法律、医疗、金融领域的语义检索），**必须用上下文相关的 Embedding 模型**（BERT 系或现代 Embedding API），静态词向量会误导检索结果。

## 小结

词向量的演进逻辑：**One-Hot 能表示词但维度爆炸且没有语义 → Word2Vec 用"预测上下文"的任务训练浅层网络，把学到的权重矩阵当作词向量 → CBOW 用上下文预测中心词（快），Skip-gram 用中心词预测上下文（生僻词更好）**。词向量能让语义关系变成向量运算，但**一个词只有一个向量，无法处理一词多义**。

Word2Vec 还留了个尾巴：**训练时没见过的词怎么办？** 这个问题的答案——子词切分——正是理解大模型 tokenizer 的钥匙，接着看 [大模型分词器：BPE、WordPiece 与 SentencePiece](article.html?slug=nlp-tokenizer-subword)。
